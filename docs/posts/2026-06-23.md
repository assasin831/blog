# 6.23 学习：SmartMall AI 秒杀安全边界复盘

今天复盘秒杀模块的安全边界。秒杀系统最怕看起来能跑，但在重复请求、活动过期、库存补偿时出错。

## 当前保护

秒杀请求进入后会经过几层保护：

1. `requestId` 幂等检查，避免同一个请求重复处理。
2. 活动有效性检查，活动未开始、已结束或暂停时拒绝请求。
3. 单用户单活动限购检查，避免同一用户重复抢购。
4. Redis Lua 原子扣库存，避免并发超卖。
5. outbox + RabbitMQ 异步建单。
6. 消费失败时补偿 Redis 库存并释放用户限购 key。

## 这次为什么补 campaignId

活动维度补齐后，库存、限购和异步补偿都能落到同一场活动上。否则一个商品多场秒杀时，状态会混在一起。
