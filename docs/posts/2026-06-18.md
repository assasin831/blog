# 6.18 学习：SmartMall AI 订单与秒杀请求索引复盘

今天主要复盘 MySQL 索引。项目做到后台分页之后，接口能跑只是第一步，更重要的是查询量上来之后不要把数据库打满。

## 重点查询场景

现在后台比较常用的查询包括：

1. 用户中心按用户查看历史订单。
2. 管理员按订单状态查看待处理订单。
3. 管理员按订单号定位问题订单。
4. 管理员按秒杀状态、商品、活动查看请求。

对应索引方向是：

```text
mall_order: user_id + created_at + id
mall_order: status + created_at + id
mall_order: order_no
mall_seckill_request: product_id + status + updated_at
mall_seckill_request: campaign_id + status + updated_at
mall_seckill_request: order_no
```

## 取舍

索引不能越多越好。现在补的都是后台查询和用户高频查询真正会用到的组合，避免为了“看起来完整”给每个字段都建索引。

## 下一步

把用户端秒杀按钮改成只在活动有效时显示，并展示活动库存和结束时间。
