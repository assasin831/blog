# 6.13 学习：SmartMall AI 秒杀 campaignId 与 Redis 库存隔离

昨天设计了秒杀活动表，今天继续把活动 ID 接到核心链路里。重点不是新增页面，而是把“活动维度”真正变成秒杀系统的一部分。

## 改造点

秒杀请求现在会先查询当前商品是否存在进行中的活动：

```text
productId -> active campaign -> campaignId
```

如果没有活动，就不允许进入秒杀链路。这样商品详情页上的普通购买和秒杀购买就不会混在一起。

Redis 库存 key 也从商品维度变成活动维度：

```text
smartmall:seckill:campaign:stock:{campaignId}:{productId}
```

用户限购 key 也同步升级：

```text
smartmall:seckill:user-campaign-product:{userId}:{campaignId}:{productId}
```

## 为什么这很重要

如果只按 `userId + productId` 限购，那么用户参加过上一场活动后，下一场同商品活动也会被误判为重复请求。活动维度加入后，限购规则就能准确落到“这一场活动”。

## 异步事件

`SeckillOrderRequestedEvent` 里也补了 `campaignId`，这样 RabbitMQ 消费者失败补偿时能找到正确的活动库存 key，而不是误补到普通商品或旧活动库存。
