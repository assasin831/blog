# 6.22 学习：SmartMall AI outbox 与 RabbitMQ 运维链路复盘

今天把消息队列链路重新梳理了一遍。SmartMall AI 现在不是直接在业务接口里同步完成所有操作，而是把用户行为、订单事件和秒杀建单逐步放到异步链路中。

## 当前链路

```text
业务请求
-> 写业务表
-> 写 outbox
-> outbox dispatcher 投递 RabbitMQ
-> consumer 处理业务
-> 成功则记录 consumed
-> 失败则进入 retry / DLQ
-> 管理员后台查看和重投
-> DLQ 重投审计落库
```

## 为什么要 outbox

如果业务表写成功但消息发送失败，系统就会出现不一致。outbox 的作用是把“要发的消息”先落库，再由后台任务可靠投递。

这比在接口里直接 `rabbitTemplate.send()` 更适合订单、秒杀这类需要最终一致性的场景。

## 今天的结论

RabbitMQ 不是单独的“性能优化工具”，它更像系统的缓冲层和解耦层。要让它真正可用，还必须配合 outbox、监控、DLQ、重投和审计。
