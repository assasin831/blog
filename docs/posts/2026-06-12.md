# 6.12 学习：SmartMall AI 秒杀活动表设计与链路拆分

这篇是补记。6.11 留下的第一件事是把“普通商品”和“秒杀商品”区分开，因为真实电商平台里，秒杀不是商品详情页上一个固定按钮，而是一场有活动时间、活动库存、限购规则和状态控制的运营活动。

## 今天补的思路

之前秒杀逻辑直接按 `productId` 做 Redis 库存 key：

```text
smartmall:seckill:stock:{productId}
```

这样实现简单，但会带来两个问题：

1. 同一个商品没法同时存在普通售卖和秒杀活动。
2. 后台无法单独控制活动库存、开始时间、结束时间和限购数量。

所以今天把目标拆成一张新的活动表：

```text
mall_seckill_campaign
```

核心字段包括：

- `product_id`
- `title`
- `campaign_stock`
- `per_user_limit`
- `status`
- `starts_at`
- `ends_at`

## 为什么要这么拆

真实业务里，商品库存是仓库库存，秒杀库存是运营分配出来的活动库存。两者不能简单混在一起，否则活动结束、活动暂停、活动限购都会很难控制。

拆出活动表后，后续链路会变成：

```text
商品详情页
-> 查询当前商品是否有进行中的秒杀活动
-> 有活动才展示秒杀入口
-> 秒杀请求绑定 campaignId
-> Redis 使用 campaignId + productId 做库存隔离
-> 异步建单仍然走 RabbitMQ / outbox
```

## 今天的收获

这一步让我更明确：秒杀模块不只是“扣库存快”，还要有运营配置能力。只有活动、库存、用户限购、状态和时间窗口都能被管理，才接近真实平台。

## 下一步

继续把 `campaignId` 接入秒杀请求表和异步订单事件，让后台能按活动维度查看请求状态。
