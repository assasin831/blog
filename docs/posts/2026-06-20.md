# 6.20 学习：SmartMall AI 管理员后台信息密度调整

今天主要看后台页面。SmartMall AI 的管理员端已经不只是商品和订单管理，还包括 MQ、outbox、DLQ、秒杀和性能快照，所以页面信息密度必须控制好。

## 调整思路

后台消息页按排障顺序组织：

```text
消息总览
-> outbox 状态
-> RabbitMQ 队列深度
-> 秒杀活动配置
-> 秒杀请求列表
-> DLQ 预览与重投
-> DLQ 审计
-> DB 性能快照
-> routing key 统计
```

这样管理员看到问题时，不需要先判断去哪一个菜单，而是顺着链路一路往下查。

## 今天的理解

真实后台不是越炫越好，而是要能在出问题时快速定位。尤其消息队列这种链路，最重要的是让状态、数量、错误和恢复入口都在同一屏附近。

## 下一步

继续补压测和观测记录，尤其关注秒杀请求分页和 DLQ 审计在高数据量下的表现。
