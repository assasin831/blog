# 6.16 学习：SmartMall AI DLQ 重投审计表设计

今天补的是 RabbitMQ 死信重投审计。之前 DLQ 已经能查看和重投，但“谁在什么时候重投了什么”还没有落库。

## 为什么需要审计

DLQ 重投是一个高风险操作。如果消息本身是因为业务 bug 进入死信，直接重投可能会再次失败；如果重投错 routing key，还可能触发错误消费者。

所以重投操作至少要记录：

- 操作者 ID
- 请求重投数量
- 实际重投数量
- 跳过数量
- 错误数量
- routing key override
- payload hash
- 操作时间

## 表结构

新增表：

```text
mall_dlq_requeue_audit
```

它不是业务表，而是运维审计表。以后如果要追查某次消息异常，就可以把 RabbitMQ 面板、outbox 表和这张审计表对起来看。

## 下一步

把审计记录接到后台页面，管理员可以看到最近的重投历史。
