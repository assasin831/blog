# 6.14 学习：SmartMall AI 管理员秒杀活动配置入口

这篇继续补记秒杀活动后台。前几天完成了活动表和活动库存隔离，但如果只能通过 SQL 插入活动，那还不算真实系统。

## 后台需要什么

我把管理员侧的秒杀活动配置拆成几个基本动作：

- 创建活动
- 修改活动标题、库存、限购、时间窗口
- 暂停活动
- 恢复活动
- 按商品或状态筛选活动

对应接口设计为：

```text
GET    /api/admin/seckill/campaigns
POST   /api/admin/seckill/campaigns
PUT    /api/admin/seckill/campaigns/{id}
PATCH  /api/admin/seckill/campaigns/{id}/status
```

## 页面设计

后台消息队列页原来已经有 RabbitMQ、outbox、DLQ 和秒杀请求列表，所以秒杀活动配置也放在同一个运维区域。这样管理员排查时可以从活动配置一路看到请求、队列、死信和订单状态。

## 今天的理解

秒杀系统的后台不是锦上添花，而是生产可用性的入口。没有后台配置，活动只能写死；没有启停按钮，线上出现异常时就只能停服务。

## 下一步

继续把秒杀请求列表从 `limit` 改成真实分页，避免请求量大之后后台一次性拉太多数据。
